# Git Flow и проверка изменений
main — проверенные выпуски; develop — интеграция. feature/<issue>-<slug> от develop. release/<version> от develop. hotfix/<issue> от main.
Разработчик создаёт коммиты, запускает проверки, открывает PR. Другой разработчик рецензирует; Tech Lead разрешает слияние после успешной проверки и одного одобрения. Автор не одобряет свой PR.
Для контракта проверять совместимость OpenAPI, валидацию и идемпотентность. Для безопасности — отсутствие секретов, доверенные claims устройства, запрет записи сырых пропусков в журнал.
Релиз вливается --no-ff в main, получает тег vX.Y.Z и вливается обратно в develop. Hotfix также переносится в develop.
На локальном стенде PR и человеческие одобрения не создавались. Процесс описан как регламент; реальные ветки и слияния воспроизводятся Git-командами.
